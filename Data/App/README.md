# QQ飞车录像分析器

把 QQ飞车 `.sav` 录像解析成可核对的分析链：地图身份 → 物理 telemetry → 原生漂移/小喷/动作 → 官方地图几何 → 驾驶分段与 A/B 对比。

本项目是本地运行的单机工具：程序只读取你自己的录像和游戏安装目录，不联网、不上传、不需要数据库。

---

## 项目用途

- 解析 `.sav` 录像，还原每一圈的实际行驶轨迹与速度。
- 按 **原生漂移动作**（replay-native Drift）切分驾驶分段，而不是按几何形状猜测。
- 统计与游戏结算口径一致的动作：空喷、落地喷、CW / WCW / CWW、逻辑漂移次数。
- 在同一张官方地图的两次录像之间做 A/B 对比：分段用时、入弯/最低/出弯速度、漂移距离、出弯→恢复距离、路线差。
- 同一个录像内部也能按圈对比（自己最快圈 vs 其它圈）。

**重要说明**：分析结果里有一部分数字是「原生证据」而不是「游戏结算口径」。无法与游戏结算闭合的量（普通小喷 code2001、氮气 code1）会明确标注为 raw / unresolved，并给出原生区间数，不会伪造成结算数字。

## 系统要求

- **Windows**（已在 Windows 10/11 验证）。
- **Windows PowerShell 5.1**（系统自带，无需安装 PowerShell 7）。
- **.NET Framework**（系统自带，用于 `Add-Type` 编译内置 C# 解析器）。
- **QQ飞车客户端已安装**：首次启动需要用游戏目录里的官方资源初始化地图资料。
- 不需要 Node.js、Python、数据库或任何第三方运行时。

---

## 第一次启动

1. 双击项目根目录的 **`启动前端.bat`**。
2. 程序会在本地启动前端服务，并自动打开浏览器（默认地址 `http://127.0.0.1:17853`；若该端口被占用会自动向后顺延）。
3. 界面右上角点 **设置**，在「QQ飞车游戏目录」里点 **选择**，选中你的游戏安装根目录。
4. 选好之后程序会在后台自动完成 **游戏资料首次初始化**（官方地图目录 + `GameMapID ↔ ResourceMapID` 绑定）。顶部状态文字会显示进度。
5. 初始化完成前 **添加录像** 按钮保持禁用；完成后再添加。

初始化只需要做一次。之后每次启动都是空操作，不会重复重建。如果以后换了游戏目录，或者想强制重建，可以在 **设置** 里点 **重新初始化游戏资料**。

---

## 设置游戏路径

- **设置 → QQ飞车游戏目录 → 选择**，在弹出的文件夹对话框里选中游戏安装根目录。
- 路径会保存到 `Data\settings.json`，下次启动自动读取。
- 路径无效或未设置时，添加录像会被禁用并提示先设置游戏目录，不会崩溃。
- 也可以手动编辑 `Data\settings.json`：

```json
{ "game_path": "你的 QQ飞车 游戏目录" }
```

---

## 添加录像

1. 点 **添加录像**，选择一个或多个 `.sav` 文件。
2. 程序把录像复制进 `Data\ReplayArchive\`（按内容 SHA256 归档，同名不同内容的录像不会互相覆盖），然后开始分析。
3. 左侧录像列表就是已导入的录像。第一张录像分析完成后，地图和分段会自动显示出来。

**注意**：添加录像要求游戏资料初始化已完成，否则会明确报错（fail closed），不会生成半成品分析。

## A/B 对比基本使用

1. 先打开一张录像（A 侧）。
2. 在界面上选择对比录像（B 侧）。默认对比圈会跟随当前圈号；没有可比圈时会明确告诉你「没有可比圈」，不会编造一个。
3. 地图上的分段就是分析器发布的分段。鼠标悬停可以预览某个分段的本地指标，点击可以锁定它。
4. 锁定后右侧面板显示这一段的本地事实：入弯速度、最低弯速、出弯速度、漂移时长、原生动作、出弯→恢复距离、路线距离。
5. 选中对比侧之后，同一分段会显示 A / B 并排数字与差值。

对比数字有几个刻意的语义：

- A / 当前 永远是蓝色，B / 参考 永远是橙色。
- 主时间差用文字表达：**快 / 慢 / 持平**，不用带正负号的数字。
- 速度按游戏显示口径（km/h）换算显示。
- 一条录像没有原生漂移时，漂移相关指标显示为不可用（—），不会填 0。
- 只有 A / B 的地图身份一致时才允许对比；地图无法权威解析时对比会被拒绝。

**路线模式**（地图上方的模式按钮）：

- `all`：显示全部路线，只看路线形状。
- `drift`：只按原生漂移本体切段。
- `recovery`（默认）：从 **起漂** 到 **原生恢复结束**。恢复终点只认 `code2001` 普通小喷；氮气、地图推进力、未知效果都不会延长分段；遇到持续的腾空（`contact_state == 0` 且 ≥100ms）会在起飞处硬切断。
- `custom`：在 A 侧地图上自定义起点/终点区间，程序把它映射成同一个世界坐标区间再做对比。

## 清空分析缓存不会删除原始录像

**设置 → 清空分析缓存**（或界面上的 **清空分析缓存** 按钮）只会删除程序生成的派生数据：分析结果、telemetry 缓存、原生动作缓存、地图几何缓存。

**会保留**：

- `Data\ReplayArchive\` 里的原始录像文件
- `Data\settings.json`（游戏目录设置）
- 用户自己的标签与手动地图名
- 已初始化好的官方游戏资料目录

也就是说清空之后重新分析一次即可，**原始录像不会丢**。

## 已知限制

- **普通小喷（code2001）与氮气（code1）的结算口径尚未闭合。** 程序发布原生区间数并标注 parity 为 unresolved，不发布对应的游戏结算数字。已知金标录像里 code2001 原生区间比游戏结算多 7 次、氮气多 1 次，原因未找到可重放的原生机制，因此不做推断。
- **部分录像变体无法对齐。** 少数录制场次的 action event 表与 `code2001` 区间完全对不上（时间基准常数偏移也救不回来）。这类录像会被判为 replay variant：只发布原生证据，扣发 game-facing 计数。
- **动态场景几何未解析。** 官方 `map.nif` 的移动/动画场景物件驱动仍未解开；`code2003` 已被确认为地图推进力效果，与场景几何无关。
- **地图身份存在少数未决项。** 资源目录可能声明冲突的游戏 MapID；冲突时程序保持 unresolved（fail closed），不会用偏移量猜一个。
- **前端是单请求串行处理。** 一次长分析进行时，其它界面请求会短暂等待。单用户本地使用可接受。
- **仅支持 Windows。** 依赖 Windows PowerShell 5.1 与 .NET Framework。
- 分析速度取决于录像大小与是否命中缓存；首次分析需要完整扫描录像尾部。

## 隐私说明

- 程序**不联网**：不发送、不上传任何数据，没有遥测、没有账号、没有云同步。
- 程序**只读取**你指定的 `.sav` 录像和 QQ飞车安装目录中的资源文件。
- 分析结果与缓存全部写在本地项目目录内。
- 录像文件名通常包含玩家昵称。这些文件只在你的本机 `Data\ReplayArchive\` 里，**不会被提交到版本库**（见 `.gitignore`）。
- 仓库中不带任何真实录像、个人配置、邮箱、令牌或机器相关的绝对路径。

## 从源码验证

程序自带验证门禁，可在解压后的根目录直接运行：

```powershell
# Fast Gate — 日常默认，不需要真实录像，约 1–2 分钟
powershell -NoProfile -ExecutionPolicy Bypass -File "Data\App\Tests\Smoke-Fast.ps1"
```

标记为 Real Regression 的测试需要真实录像语料（放在 `Data\ReplayArchive\`）。**全新安装没有这些录像时它们会被跳过，这是预期行为**，Fast Gate 不受影响。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "Data\App\Tests\Smoke-RealRegression.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File "Data\App\Tests\Smoke-Full.ps1"
```

`Data\App\docs\ARCHITECTURE.md` 描述当前的权威（authority）边界；`Data\App\docs\decisions\` 记录重大设计决策的来龙去脉。
