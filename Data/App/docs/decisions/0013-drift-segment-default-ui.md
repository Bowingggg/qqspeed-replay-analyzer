# ADR 0013 — Drift-segment default UI contract

Status: accepted for Product UI v8

## Decision

The default replay-analysis surface is fixed to the following rules until explicitly changed by the user:

1. A multi-lap replay opens on **lap 1**. The UI must not silently select the fastest, second or last lap. When a different replay is explicitly chosen for comparison, its comparison-lap selector defaults to the **same lap number as the current lap** when that lap exists. It must not silently fall back to a fastest/second/last lap. Self-comparison excludes the current lap, so another lap remains an explicit user choice.
2. Official basemap availability and replay comparability are separate capabilities. Replays remain comparable when they have the same authoritative Resource/Game identity **or the exact same displayed map name**. A missing basemap must not disable same-name replay comparison. For display only, an unresolved replay may reuse an official basemap from another active replay with the exact same map name only when that name resolves to exactly one ready ResourceMapID among active replays; this does not promote map-identity authority.
3. Default automatic segmentation is **Drift-derived only**. It starts from the replay-native logical Drift episodes assigned to the current lap. Consecutive logical Drift episodes are merged into one UI Drift segment when the gap from the previous Drift end to the next Drift start is **strictly less than 0.15 s**. The segment starts at the first Drift start and ends at the last merged Drift end. Percentage/curvature/route geometry does not create default segments.
4. Drift ownership is determined by the existing native Episode lap assignment (the Drift-start lap). If a Drift segment starts in lap N and ends after the lap boundary in lap N+1, the UI must retain the complete trajectory through the Drift end; it must not clip that segment at the lap boundary. This changes only the UI view extent, not lap timing or native ownership.
5. When comparing another lap/replay, the current lap's Drift-segment start/end world positions are mapped monotonically to the comparison trajectory; the comparison side's own Drift count does not redefine the current segment.
6. The route canvas has three primary display modes:
   - **All route**: draw the complete selected-lap trajectory. Drift markers may remain as navigation anchors, but this mode publishes **no segment time judgement**.
   - **Drift-only**: draw the UI Drift segments. A time delta is published only when the comparison trajectory has exactly one Native Drift overlapping the mapped spatial region; no Drift means “not drifted” and no Drift-time delta, while multiple independent Drifts remain ambiguous rather than being forced into one.
   - **Drift-start → native recovery end**: start from the analyzer-published native Drift start and continue only to the published recovery end. Recovery ownership is deliberately narrower than generic propulsion: only an eligible post-Drift `code2001` small-boost-class effect may extend the segment; standard Nitro/`code1` is evidence-only and never extends it. If no eligible small-boost exists, the segment ends at the native Drift end. The comparison side participates over the analyzer's shared world interval even when it does not Drift at that location.
7. Recovery extension is native-effect-driven and bounded by a **2.0 s onset search** after the Drift end. The window bounds only when an eligible `code2001` small-boost may start. Once recovery is owned, the first sustained replay-native `contact_state == 0` interval (>=100 ms) hard-cuts the automatic segment at take-off; the next independent Drift start is the other hard cut and the earlier cut wins. Airborne/Nitro/landing continuation is intentionally left to Custom Path. No speed peak, curvature or geometry heuristic may extend the segment.
8. For a **paired** Drift-start→recovery comparison, the primary `快/慢` time uses a core shared window: start at the earlier mapped Drift start, stop at the earlier mapped natural recovery end. A longer single/double-spray recovery tail must not enlarge the primary efficiency interval. Each side's own exit speed / recovery distance / total distance still uses its complete natural recovery metric window and is never clipped to this core time window.
9. The product presents a second **final net result** for paired recovery comparison. It uses the same shared start as item 8 and extends to the later mapped natural recovery end, with the next independent Drift on either side as a hard cut. The map label and large Current Segment result display this final net time difference. The inspector separately displays the core time result and the recovery-strategy gain (`core_delta - final_delta`) so a corner-handling advantage and a single/double-spray recovery advantage are not conflated.

## Non-decisions

This ADR does not claim that one UI Drift segment is permanently equivalent to one human-defined corner. It fixes the current default segmentation requested by the user while preserving the replay-native logical Drift episodes as the underlying authority. More advanced corner grouping may be added later as a separate capability.
